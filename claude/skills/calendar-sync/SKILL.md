# GoogleカレンダーとTimeTree同期スキル

GoogleカレンダーとTimeTreeの予定をブラウザ操作で双方向に同期する。今日から1ヶ月先までの予定を対象とし、片方にしか存在しない予定をもう片方に作成する。

## 前提条件

- Playwright MCPが利用可能であること
- GoogleカレンダーとTimeTreeにブラウザからアクセスできること

## 同期の流れ

### Step 1: Googleカレンダーから予定を取得

1. `browser_navigate` で `https://calendar.google.com` を開く
2. `browser_snapshot` でページの状態を確認する
3. **ログインチェック**: ログイン画面が表示された場合は、ユーザーに以下を伝えて手動ログインを依頼する：
   - 「Googleカレンダーにログインしていません。ブラウザでログインしてください。完了したら教えてください。」
   - ユーザーが完了を報告するまで待機する
4. カレンダーの表示を「スケジュール」ビューに切り替える（予定の一覧性が高いため）
5. `browser_snapshot` や `browser_run_code` を使い、表示されている予定を取得する
6. 1ヶ月先までの予定をカバーするため、必要に応じてスクロールや日付移動を行う
7. 各予定について以下の情報を収集する：
   - タイトル
   - 開始日時
   - 終了日時
   - 終日かどうか

**効率的な取得方法**: `browser_run_code` でDOMから直接予定データを抽出するのが最も効率的。スナップショットだけでは全予定を取得しきれない場合がある。スケジュールビューでスクロールしながら段階的にデータを収集する。

### Step 2: TimeTreeから予定を取得

1. 新しいタブを開き、`browser_navigate` で `https://timetreeapp.com/calendars` を開く
2. `browser_snapshot` でページの状態を確認する
3. **ログインチェック**: ログイン画面が表示された場合は、ユーザーに以下を伝えて手動ログインを依頼する：
   - 「TimeTreeにログインしていません。ブラウザでログインしてください。完了したら教えてください。」
   - ユーザーが完了を報告するまで待機する
4. 全てのカレンダーを対象として予定を取得する
5. 月表示を使い、今日から1ヶ月先までの予定を収集する
6. 各予定について以下の情報を収集する：
   - タイトル
   - 開始日時
   - 終了日時
   - 終日かどうか
   - 予定の色

**色によるフィルタリング**: TimeTreeでは予定ごとに色が設定されている。同期対象は**青・紫・緑・黄色**の予定のみ。**赤・ピンク**の予定は無視して取得対象から除外すること。予定の色はDOM要素のスタイルや属性から判定する。

### Step 3: 差分を特定する

両方の予定リストを比較し、差分を特定する。

**一致判定の基準**: タイトルと日時（開始・終了）が一致する予定は「同じ予定」と判断する。

- **Googleにのみ存在する予定** → TimeTreeに作成する対象
- **TimeTreeにのみ存在する予定** → Googleカレンダーに作成する対象

差分の一覧をユーザーに提示し、確認を取ってから次のステップに進む。これは意図しない予定の作成を防ぐために重要。

### Step 4: 予定を作成する

#### TimeTreeに予定を作成する場合

1. TimeTreeのタブに切り替える
2. 予定作成ボタン（「+」など）をクリック
3. タイトル、日時を入力して保存
4. 各予定について繰り返す

#### Googleカレンダーに予定を作成する場合

1. Googleカレンダーのタブに切り替える
2. 予定作成ボタンをクリック
3. タイトル、日時を入力して保存
4. 各予定について繰り返す

### Step 5: 結果を報告する

同期結果をユーザーに報告する：

- Googleカレンダーから取得した予定の数
- TimeTreeから取得した予定の数
- TimeTreeに新規作成した予定の一覧
- Googleカレンダーに新規作成した予定の一覧
- エラーがあった場合はその内容

## 注意事項

- ブラウザのUIは変更される可能性がある。`browser_snapshot` で常に現在の状態を確認してから操作すること
- 予定の作成前に必ずユーザーに差分一覧を見せて確認を取ること
- 日時のタイムゾーンに注意する。両サービスで同じタイムゾーンが設定されている前提で動作する
- 大量の予定がある場合はページングやスクロールで全件取得する
- 操作中にエラーが発生した場合は、その時点でユーザーに報告し、続行するか確認する
